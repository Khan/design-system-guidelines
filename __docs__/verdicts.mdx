# Verdicts

Design Infra's rulings on how Wonder Blocks is meant to be used (Judge Trudy). Each ruling is tied to a component in code. The prototype builder's audit applies them, so every prototype gets the same answer.

**Rulers:** Caitlyn Mayers, Camila Hernandez, Jonah Goldsaito. **Requests:** #design-infra. A ruling is a thread reply that starts with `Ruling:`, and it counts once it's merged into `verdicts/verdicts.json`.

## Rulings (3)

### K1 · Not an issue

- **Applies to:** `ActivityIconButton` (style override) · shared style `sharedStyles.adjustedTooltipIconButton`
- **Ruling:** [This is not an issue, evidence is correct.](https://khanacademy.slack.com/archives/C0BHXK7RFFE/p1793224106492179)
- **Reason:** ActivityIconButton's `label` prop with its documented `styles` prop (root / label), setting position and margins only, so the tooltip centres on the button. Layout through style props is what Wonder Blocks expects.
- **Ruled by:** Caitlyn Mayers on 2026-10-28 (requested by Caitlyn Mayers)
- **Guideline:** None yet
- **Guidance needed:** Customizing ActivityIconButton: layout through the documented styles prop isn't drift
- **Follow-ups:** F1

### K2 · Wonder Blocks gap — Practice content panel: no Wonder Blocks scaffolding component for this surface

- **Applies to:** uses WB `Card` · in `libs/content/renderer/core/src/components/content-panel/content-panel-card.tsx`
- **Ruling:** [Finding is correct, the card is not appropriate but this is flagged as a need to add to WB as some form of scaffolding component.](https://khanacademy.slack.com/archives/C0BHXK7RFFE/p1793224123101069)
- **Reason:** Wonder Blocks gap: likely needs scaffolding components (e.g. the practice container surface). Not a component swap.
- **In prod:** ContentPanelCard, the practice page's main surface, is built on WB Card.
- **What to do:** Not in Wonder Blocks yet. Wonder Blocks likely needs a set of scaffolding components that give componentized versions of surfaces like the practice container. Until they exist, this is known debt: don't swap Card for a hand-built View-and-tokens surface.
- **Ruled by:** Caitlyn Mayers on 2026-10-28 (requested by Caitlyn Mayers)
- **Guideline:** [Surfaces and elevations describes this surface (content panel / question card: Surface 2, Low elevation on a busy practice page) but not which component builds it.](https://khan.github.io/design-system-guidelines/?path=/docs/design-guidelines-foundations-surfaces-and-elevations--docs)
- **Guidance needed:** Which component builds a page surface like the practice content panel (Surface 2)
- **Follow-ups:** F2, F3

### K3 · Not an issue

- **Applies to:** `ActivityIconButton` (style override) · in `libs/content/renderer/component/tools/src/renderer-tools/doodlepad/components/drawing-area-controls.tsx` · local styles `styles.closeButton`, `styles.horizontalCloseButton`, `styles.compactCloseButton`
- **Ruling:** [Designer reason is correct, accept.](https://khanacademy.slack.com/archives/C0BHXK7RFFE/p1793224315331299)
- **Reason:** The drawing toolbar's close button removes two corner radii so it attaches to the tool group it opens and closes. This attached-toggle pattern is used only here, so Wonder Blocks doesn't need to accommodate it; the control's design isn't the problem.
- **Ruled by:** Caitlyn Mayers on 2026-10-28 (requested by Caitlyn Mayers)
- **Guideline:** None needed
- **Separate accessibility issue:** Drawing toolbar close button: accessible name changes with layout and mixes disclosure and action semantics (owner: Practice surface team). Not decided. Logged only; Design Infra decides later what to do, and nothing is filed until then.
- **Follow-ups:** F4
