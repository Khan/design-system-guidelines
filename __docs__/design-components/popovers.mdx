# Popovers

<NeutralBadge label="Rich contextual overlay" />

A non-modal overlay that displays rich content — text, links, icons, or illustration — anchored to a specific UI element. Some popovers open in response to the user; others are raised by the product. Unlike tooltips, popovers are designed for larger bodies of info and interactive content.

## When to use

The choice to use a popover is determined by the need to provide supplemental information or micro-tasks that are too complex for a tooltip but do not require the full interruption of a modal.

| Use when | Example use |
| --- | --- |
| Displaying formatted text, headers, or small snippets of info | Explaining a specific exercise, skill name, and score, e.g. "Familiar." |
| The overlay needs to contain clickable links, buttons, or small forms | A popover that includes a "Jump here" button to navigate the user to a specific activity. |
| Delivering transient, proactive feedback that requires user acknowledgement | Khanductor appearing in a popover to say "Slow down just a bit" with a "Got it" button during an assessment. |
| A specific on-screen element needs contextual guidance or a nudge tied directly to it | A popover anchored to the gem counter, showing the student where to check progress toward their next accessory. |

## When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| The content requires extensive reading across multiple paragraphs | Modal | An anchored overlay gives the reader nowhere to settle into a long passage, and a stray click elsewhere dismisses it partway through. |
| Only a simple, unformatted identification label is needed | Tooltip | A popover introduces a structured overlay with padding, elevation, and potential actions — all unnecessary overhead for a single identifying label. Tooltips are lightweight by design. |
| The user must complete a complex task or make a destructive choice | Modal | A popover leaves the background live, so nothing stops the user acting elsewhere mid-task — and a destructive choice needs the deliberate pause a modal forces. |
| The message requires the user’s full attention before proceeding | Modal | Popovers are anchored to a specific UI element and non-blocking — they can’t command full attention the way a modal can. |

## Variants

Each variant serves a distinct use case. Choose based on the intent of the content — what the user needs to do or understand when the popover appears.

### Informational

Focuses on providing additional context as succinctly as possible, such as exercise names and learner scores. Typically action-oriented, including a button for immediate navigation — e.g. "Jump here" — task completion, or more info to read.

### Feature highlight

Used for single-step guidance only.

### System guidance

Used for transient, proactive feedback from the system that requires user acknowledgement.

## Usage and purpose by variant

| Variant | Purpose | Example |
| --- | --- | --- |
| Informational | To surface contextual detail about a specific UI element without leaving the page. | Explaining an exercise name, skill level, and score inline with the learning queue. |
| Feature highlight | To introduce a new feature in context, anchored to the relevant UI element, without interrupting the user's flow. | Onboarding a student to the gem counter and rewards system after first login. |
| System guidance | To deliver proactive feedback from the system that requires acknowledgement before continuing. | Khanductor prompting "Slow down just a bit" during an assessment. |

## Character illustration

Use a character illustration when the message is delivered on behalf of a named system character — Khanmigo (tutor) or Khanductor (proctor). The character signals the source of the message and adds personality to system-initiated communication.

The illustration is optional and available in System guidance only. If neither character is the source, use text only or a feature image instead. Feature highlight and Informational popovers never carry a character.

<img src={withCharacterImg} alt="A popover with the Khanductor character illustration to the left of the “Slow down just a bit” message and a “Got it” button" />

## Buttons

A popover contains no more than two buttons — one primary and one tertiary. More than that signals a task too large for an anchored overlay; use a modal instead.

| Variant | Buttons |
| --- | --- |
| Informational | Optional. Where present, a single action for navigation or task completion — e.g. "Jump here". |
| Feature highlight | A single acknowledgement action — e.g. "Got it". |
| System guidance | Always a primary acknowledgement action — e.g. "Got it" or "Okay". A tertiary action is optional. |

## Placement

### Adaptive relative anchoring

Popovers must always anchor and appear from the content that triggered them. When they prefer "above" or "below" placement, they must flip to the opposite or reverse orientation if they would be clipped by the viewport edge.

## Interaction

### Opening

Informational popovers open in response to the user, from the element they are anchored to. Feature highlight and System guidance popovers are raised by the product, at a moment the product chooses.

### Dismissal

Every popover can be closed without acting on it. Selecting outside the popover closes it, as does pressing Escape. Where the popover carries an acknowledgement action, selecting that action closes it too.

A popover never closes on a timer. It is not a toast, and content the user may still be reading must not disappear on its own.

### One at a time

Only one popover is open at a time — opening a second closes the first. A popover and a modal never appear together: a modal blocks the background, which is where the popover’s anchor lives.

### Focus

A popover opened by the user takes focus, so its buttons and links are immediately reachable by keyboard. Closing it returns focus to the element that opened it.

A popover raised by the product does not take focus. Pulling a user out of what they were doing is the interruption these popovers exist to avoid. Instead it is announced politely to assistive technology and placed immediately after its anchor in the tab order, so the user reaches it on their next Tab rather than being dropped into it.
