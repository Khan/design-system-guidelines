# Search field

<NeutralBadge label="Keyword filtering" />

A specialized text input used to accept user-entered keywords or strings to instantly narrow or filter content based on those terms. It is the primary mechanism for finding specific items within large data sets or complex navigation structures.

## When to use

The choice to use a search field is determined by the need to efficiently locate specific information that cannot be easily found using predefined filters or navigation.

| Use when | Example use |
| --- | --- |
| The content list contains more than 10–15 items, making visual scanning difficult | Finding a specific student name within a class roster of 40 students. |
| The user is searching by a specific identifier, name, or non-categorical string | Searching for "Pythagorean Theorem" in a library of math lessons. |
| The dataset is too large for live-filtering and requires explicit submission | Typing a partial class name and hitting enter to refresh the report table. |

## When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| The available options are fixed, small, and mutually exclusive | Dropdown, checkbox, or radio group | Typing to reach one of a handful of known options is slower than picking from them, and it forces the user to guess the exact wording. |
| The user is narrowing a preference with a binary choice | Toggle / checkbox | For binary choices like "Show assigned skills only," use a toggle instead of a search query. |
| The input is intended to collect new data, not retrieve existing data | Text field | Search styling promises retrieval. A field that looks like search but stores what the user types misrepresents what the input does. |

## States

### Default / active

The search field is bordered and displays placeholder text like "Search." When active, the input must change appearance to clearly indicate active typing.

## Placement

### Contextual placement

The search field must be placed immediately adjacent to the content list or data set it controls. It should never float or sit distant from the elements it is meant to filter.

<img src={contextualPlacementImg} alt="A report page with the search field placed directly above the results table it filters, alongside the other filter controls" />

## Interaction

### Clear button

Once text is entered, a clear button (an X) appears inside the field so the user can erase the query without selecting and deleting the text.

Selecting it clears the field and submits in a single action, restoring the unfiltered list. This is not an exception to the submission rule — that rule exists to stop results churning on every keystroke, and clearing is one deliberate action. Leaving the results filtered after the field is emptied would show an empty search box above a narrowed list, which states two contradictory things at once.

Focus stays in the field after clearing. A user who clears a search is usually about to type a different one. This differs from Clear filters, where the button removes itself when activated and focus has to be moved deliberately.

<img src={clearButtonImg} alt="A search field with a text cursor and a clear “X” button at the end of the input" />

A search term is cleared only from the field. It does not produce an active filter, and Clear filters does not remove it — a user who clears all filters while a search is still applied will see results that remain narrowed by the search term. See [Active filters](?path=/docs/design-guidelines-components-inputs-active-filters--docs) and [Clear filter](?path=/docs/design-guidelines-components-inputs-clear-filter--docs).

## Copy

The placeholder names what the field searches rather than labelling the field. "Search students" tells the user the scope; "Search" on its own leaves them guessing whether it covers the table, the page, or the whole product.

Write placeholders in sentence case with no ending punctuation — "Search students", not "Search students…" or "Search."

Where the scope is too broad to carry in a placeholder, pair the field with an adjacent scope selector so the user can see and change what is being searched.
