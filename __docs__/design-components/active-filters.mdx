# Active filters

<NeutralBadge label="Active filter feedback" />

Compact visual elements that provide transparent feedback on the current dataset. In our reporting interface, they are primarily used to display active filter selections directly below the filter bar.

## When to use

The choice to use active filters is determined by the need to provide immediate visibility into how a data view has been narrowed and to allow for modular management of active parameters.

| Use when | Example use |
| --- | --- |
| The user needs to see what filters are currently applied | Showing "Grade: 6th grade" after selecting from the Grades dropdown. |
| Individual filters should be removable without resetting all others | Removing only "Subject: Math" while keeping school and date filters active. |

## When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| The element represents navigation or view switching | Tabs or segmented controls | Active filters represent transient filter states, not primary page navigation. |
| The element is a static, non-removable label | Status badge | If the element can’t be dismissed, it’s not an active filter — it’s a status indicator. |
| The user hasn’t made a selection yet | No active filter — leave the row empty | Active filters are the result of a selection, not a prompt to make one. |

## What generates an active filter

Not every control in the filter bar produces a chip. The test is whether the control's own display already shows the complete, specific value at a glance. If a selection is short and fully legible on the control itself (like "Last 30 days"), a chip would just repeat it. If the control has to truncate long text or summarize multiple selections as a count (like "School: Addison Middle..." or "Grades: 2 selected"), a chip is what actually tells the user the full, specific value — one chip per value when multiple are selected.

| Control type | Generates an active filter? | Why |
| --- | --- | --- |
| Standard dropdown or inline filter button | Yes | Long or multi-value selections get truncated or summarized as a count on the control itself (e.g. "Addison Middle...", "2 selected") — chips restore full legibility, one per value when multiple are selected. |
| Embedded filter dropdown (e.g. Date, defaulting to Last 30 days) | No | Preset values are designed to stay short and complete on the control itself (e.g. "Last 30 days," "Last 7 days"), so nothing needs to be hidden or truncated. |
| Search field | No | The typed term is fully visible in the field itself. |
| Toggle | No | Its on/off state is a complete, unambiguous indicator, always visible on the control. |
| Segmented control | No | The selected segment stays fully visible and highlighted on the control itself. |

## States

Each active filter displays the filter category and its selected value — for example, "School: Addison Middle School." A dismiss icon allows the user to deactivate that specific filter.
When more active filters exist than can fit on one line, they wrap to a second line to maintain full transparency.

## Placement

Active filters sit directly below the filter bar, creating a clear visual link between the controls and the data they affect.
They sit above the data visualization — cards, charts, or tables — acting as a bridge between the filtering interface and the displayed data.

## Copy

Use the format [Category]: [Value] — for example, "Subject: Math." This ensures users can immediately understand what each chip represents without needing to open the dropdown to check.

For multi-select filters, each selected value gets its own chip rather than combining them into one — "Grade: 6th grade" and "Grade: 7th grade" as two chips, not "Grades: 6th, 7th" as one. This keeps each value individually scannable and removable.
