# Dropdown select

<NeutralBadge label="Dimension/Selection control" />

A selection control used in forms, modals, settings panels, and filter bars. Can start empty or with a product default. Single-select and multi-select variants.

## When to use

The choice to use a dropdown is based on the need to select from a predefined list of options — either one value or multiple.

| Use when | Rule | Example use |
| --- | --- | --- |
| Selecting a single value | One option must be chosen from a list | Selecting a course in a filter bar or form |
| Selecting multiple values | More than one option can be chosen simultaneously | Selecting multiple grades to filter a report |
| List is too long for radio buttons or checkboxes | More than ~5 options benefit from a compact list | Selecting a school from a district-wide list |

## When NOT to use

| Don't use when | Recommended alternative | Rationale |
| --- | --- | --- |
| Only 2–3 options exist (unless part of the filter bar) | Radio buttons or checkbox group | Visible options reduce clicks and cognitive load |
| The user is opting in to filter | Filter combobox | The filter combobox pattern is designed for additive, clearable filtering |
| Filtering by a time period | Date filter | The date filter handles temporal filtering with predefined relative options |

## Variants

### Label above

The field label sits above the input. Used in forms and modals where vertical space allows and the label needs to be prominent.

<img src={labelAboveImg} alt="Two stacked dropdowns with their labels above the field: a “Course” dropdown showing the placeholder “Select a course” and a “State” dropdown showing “Algebra 1”" />

<img src={exampleComingSoonImg} alt="A placeholder tile reading “Example coming soon”" />

### Label inline

The label sits inside the field to the left of the value. Used in filter bars and compact layouts where horizontal space is shared across multiple fields.

<img src={labelInlineImg} alt="Two inline-label dropdowns: an empty “Select a course” and one reading “Course: Algebra 1” with the label inside the field" />

<img src={labelInlineFilterBarImg} alt="An inline-label “Course: Algebra 1” dropdown highlighted within a report’s top filter bar, alongside Search report, School, Grade, and More filters" />

<img src={labelInlineModalImg} alt="An inline-label “Course: Algebra 1” dropdown highlighted inside a “More filters” modal, below the Display options toggles" />

### Single-select

One option can be selected. Selecting immediately applies and closes the menu. A filled blue circle with a checkmark marks the active item.

<img src={singleSelectImg} alt="An open single-select menu listing Geometry 1, Algebra 1, and Algebra 2, with Algebra 2 marked active by a filled blue checkmark circle" />

### Multi-select

Multiple options can be selected via checkboxes. A search field appears for long lists. Changes are not applied until the user taps Apply. The trigger label after selection shows the item name when one is selected, and "2 selected", "3 selected", and so on when more than one is selected.

<img src={multiSelectImg} alt="An open multi-select menu with grade checkboxes and an Apply button; after applying, the trigger collapses to read “Grade: 6th grade”" />

<img src={multiSelectTwoImg} alt="An open multi-select menu with two grades checked and an Apply button; after applying, the trigger collapses to read “Grade: 2 selected”" />

## States

These states apply primarily to the label-above variant, which has vertical space for context labels, helper text, and error messages. The inline variant may support some states depending on context, but the label-above variant is the default for stateful interactions.

### Context

Use "Required" as an inline label next to the field label instead of an asterisk. This is more accessible and explicit — users don't need to find and interpret a legend.

<img src={stateContextImg} alt="A “Grade” dropdown with a “Required” label to the right of the field label instead of an asterisk" />

### Helper text

Used for helpful description text that would otherwise be hidden in a placeholder. Helper text is persistent — it stays visible before and after the user makes a selection. Use it when the context genuinely aids the user's decision.

<img src={stateHelperTextImg} alt="A “Primary language” dropdown with persistent helper text explaining that languages marked with an asterisk are not fully quality-tested" />

### Error

If the user submits or taps Apply without selecting a required item, the dropdown gains a red border and displays an actionable error message below the field. The label also turns red. The error clears once a valid selection is made.

<img src={stateErrorImg} alt="A “Grade” dropdown in its error state: red label, red border, and the message “Select at least one grade” below the field" />

### Read only

Displays the current value while explicitly preventing interaction. Unlike disabled, read-only maintains clear color contrast — the content is still meant to be read. Always include helper text explaining why the field is locked.

<img src={stateReadOnlyImg} alt="A read-only “Class” dropdown showing “Period 3, Precalculus” with a lock icon and the helper text “Only teachers can edit this”" />

### Disabled

Used when a prerequisite action has not been fulfilled. The field is grayed out and non-interactive. Once the dependency is met, it no longer displays as disabled. Do not use disabled when read-only is more appropriate — disabled implies unavailability, not restriction.

<img src={stateDisabledImg} alt="A grayed-out, non-interactive “Grade” dropdown in its disabled state" />

## Interaction

### In-menu search

Add a search field inside the menu when the list is long or when users are likely to know the specific item they need. Applies to both single-select and multi-select. Trigger conditions:

-   **Large data sets:** the list contains more than 10–15 items or requires significant scrolling.
-   **Known-item search:** users are likely to know the specific name of the item they're looking for (e.g., a specific school, student, or unit).
-   **Alphabetical / categorical lists:** the list is long enough that manual scanning becomes inefficient.

<img src={inMenuSearchImg} alt="An open “Select school(s)” menu with a “Search schools” field at the top above a scrollable, checkbox list of schools" />

### Multi-select requires apply

Checking or unchecking items does not apply until the user taps Apply. This prevents the data from re-filtering on every checkbox tap, which would be disorienting.

<img src={multiSelectApplyImg} alt="A multi-select grade menu with two boxes checked and an Apply button, collapsing to a “Grade: 2 selected” trigger only after Apply is tapped" />

## Copy

### Label clarity and truncation

Option labels must be clear, concise, and immediately understandable, avoiding ambiguity, jargon, or excessive abbreviation. The label displayed in the closed dropdown must fit on a single line and truncate with an ellipsis (…) if necessary, to prevent line wrapping and maintain the component's compact footprint.

<img src={copyTruncationImg} alt="Side-by-side comparison: a recommended dropdown truncating “12 grade advanced placeme…” on one line, versus a discouraged dropdown wrapping “12 grade advanced placement” onto two lines" />

### Logical ordering

Order options logically. This can mean arranging them alphabetically, numerically, by popularity, or by functional grouping, depending on what best supports the user's scanning process.

<img src={copyOrderingImg} alt="Two menus showing ordering strategies: a status list ordered by functional grouping (To do, In progress, Complete) and a state list ordered alphabetically (Alabama, Alaska, Arizona)" />
