# Progress charts

<NeutralBadge label="Progress toward a goal" />

Progress charts answer "How close are we to the goal?" A progress bar shows a current value against a goal, and can mark where the group should be by today. Progress means how far along, never how well. A progress chart never shows a score or outcome.

Progress charts sit inside a <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs">chart container</a>, large or small.

## <Do /> When to use

| Use when | Example use |
| --- | --- |
| Readers need to see how far along they are toward a goal | Gems toward a class challenge, or assignments completed toward a school or district goal |
| Readers need to see whether progress is on track for a deadline | Assignments completed against where the class is expected to be by today |
| Readers need to see how much of a task is done | Students who finished an assignment or assessment |

## <Dont /> When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| Readers only need to know ahead or behind, not how far along the goal they are, like "The class is 3 skills ahead of schedule" | A <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs#stat-card">stat card</a> | Plain text is faster to read than a chart to decode. Use a bar when seeing how much of the goal is left matters. |
| Showing a score or outcome, like Beginning, Approaching, or Demonstrating | <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs#grouped-by-level">Distribution charts</a> grouped by level | A bar reads as how far along, not how well. A full bar would look like success even when scores are low. |
| There's no goal | <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs">Summary cards</a> | Progress needs something to measure against. Without a goal, a bar's length means nothing. |
| Readers need to see how progress changed over time | <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend charts</a> | A progress bar shows where things stand today, not how they got there. |

| Part | Rule | Example |

| Value and goal | Always as text, not only as bar length | 1,245 of 1,500 gems |

Gem challenges and other motivation goals use the <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#motivation">Motivation</a> color role.

### Expected by today

Expected by today is where the group should be by today to reach the goal on time. It spreads the goal evenly across school days, so it doesn't move on weekends or holidays.

## Container

### Large container

For reports. The title states whether the group is ahead of or behind schedule.

| Part | Example |
| --- | --- |
| Section heading | Grade level target |
| Title | 3 skills ahead of schedule |
| Description | 38 of 70 skills · Goal date May 29 |
| Controls | Download |
| Bar | With a labeled expected by today marker, and start and end labels |
| Footer | Updated today, 9:15 AM |

Label the bar's values directly. A legend isn't needed when the value and the marker are labeled.

### Small container

For dashboards and side panels, like the student dashboard. Keep it to the bar and a few values.

| Part | Example |
| --- | --- |
| Title | Gem challenge, with an info tooltip |
| Context | Period 3, Precalculus |
| Illustration | Optional, like a trophy |
| Bar | No marker |
| Time left | 1 day left |
| Value and goal | 1,245 of 1,500 gems |
| Details | Up to two rows, like Your contribution: 217 and Reward: Pizza party |

<ul>
    <li><Do /> Keep a small container to one bar and up to four values.</li>
    <li><Dont /> Add controls, a legend, or an expected by today marker to a small container. If readers need them, use a large container.</li>
</ul>

## Usage guidelines

### Title and description

<ul>
    <li><Do /> State the gap in the title of a large container: "3 skills ahead of schedule," not "Class is ahead of schedule."</li>
    <li><Do /> Show the current value and the goal as text, not only as bar length.</li>
</ul>

### Values

<ul>
    <li><Do /> Show the value as "X of Y," with units: "38 of 70 skills."</li>
    <li><Dont /> Fill the bar past 100%. Say "Goal reached" and show the final value.</li>
</ul>

### Bars

<ul>
    <li><Do /> Show one kind of progress per container. In Comparing groups, every bar measures the same thing toward the same goal.</li>
    <li><Dont /> Mix measures in one container, like skills in one bar and assignments in another.</li>
    <li><Do /> Label the expected by today marker with its value: "Expected by today: 35."</li>
    <li><Do /> When some groups are behind schedule, highlight them with the <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#emphasis">Emphasis</a> role and say so in the title: "2 of 5 schools are behind schedule."</li>
    <li><Dont /> Show progress as a gauge or dial. Gauges are harder to read and compare, and take more space for the same value.</li>
</ul>

## Accessibility

- Every progress chart has a text summary: "38 of 70 skills. Expected by today: 35. 3 skills ahead of schedule."
- Read the value and goal as text: "1,245 of 1,500 gems."
- Announce the expected by today marker with its value: "Expected by today: 35."
- Color is never the only signal. The title or values say whether the group is ahead or behind.
