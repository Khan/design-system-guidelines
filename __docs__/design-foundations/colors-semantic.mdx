# Semantic Tokens
Semantic color tokens are a second tier of abstraction that organizes color by concept and purpose they serve within the system / our interfaces. When working with color, Core tokens are the preferred tokens set to use in Designs and Code.

## Schema

Within the semantic palette, tokens are organized using the following schema:

- Domain
    - Layer
        - Context
            - Intensity

### Domain

A domain represents the scope, role, or application of a collection of tokens within the system. Wonder Blocks color tokens have 4 domains: Core, Learning, Internal, and Graphics.

### Layer

Tokens within a domain are organized by role, each representing different layers of the UI. 

- Background
- Border
- Foreground
- Shadow

**Background**

Background tokens style the fill color of a component or element’s container.

**Border**

Border tokens style defining borders around or separators between elements.

**Foreground**

Foreground tokens style text or icon elements that sit on top of the background of a component or view.

**Shadow**

Shadow tokens add depth and elevation to a component or element in a design.

### Context

Within each layer, tokens are organized by context — the expected application or purpose of the hue.

| Core | Learning | Internal | Graphics |
| --- | --- | --- | --- |
| <ul><li>Base</li><li>Instructive</li><li>Neutral</li><li>Disabled</li><li>Success</li><li>Warning</li><li>Critical</li><li>Knockout</li><li>Overlay</li></ul> | <ul><li>Math</li><li>Gems </li><li>Streaks</li><li>Due</li><li>Mastery / Progress</li><li>Role</li></ul> | <ul><li>Action (Figma use only)</li><li>Feedback</li><li>Focus</li><li>Input</li><li>Link</li><li>Progress (not in code yet)</li><li>Tiles (not in code yet)</li></ul> | <ul><li>Palette</li><li>Characters</li><li>External Brands</li><li>Gems</li><li>Progress</li><li>Role</li><li>Streaks</li><li>Neutral</li></ul> |

### Intensity Scale

The intensity scale provides three values available to use within each Context. The intensity is determined by the amount of contrast and visual weight a given value has relative to the Core Base Default token, which serves as the anchor color from which the Subtle and Strong values are determined. Subtle intensity has lowest contrast against and Strong intensity has the highest contrast against this anchor value.

### Example

**Domain: Core**

- Layer: Background
    - Context: Instructive
        - Intensity: Subtle
        - Intensity: Default
        - Intensity: Strong

This schema is designed to be shared between domains. Some tokens in both the Core and Learning domains have consistent layer and intensity structures, while the Contexts vary based on the Domain.

Now that we’ve outlined the schema for our semantic tokens, let’s take a deeper look at how these concepts work in practice across our Color system.

## Core Tokens

Core tokens are intended to power a majority of the components in the Khan Academy experience. These tokens are largely scoped to the system’s functions — its rules and opinions.

### Contexts

Core token Layers share the following 9 contexts:

- Base
- Instructive
- Neutral
- Disabled
- Success
- Warning
- Critical
- Knockout
- Overlay

#### Base

Base tokens are available only as Background tokens. Base tokens style a majority of the background colors across the Khan Academy experience. The Default Base token is the anchor token used to calculate the intensity of the other tokens in the system.

#### Instructive

Instructive tokens style elements that serve as main elements and actions within a view. Instructive tokens guide users to the most intended actions in a view, typically actions that advance the user to another step in the flow, complete a progressive (non-destructive) action, or communicate general interactivity.

#### Neutral

Neutral tokens style elements without conveying additional meaning through the visual presentation. Neutral tokens help preserve hierarchy balance when multiple kinds of elements with differing visual weights are present in a view.

#### Disabled

Disabled tokens style elements that users are actively prevented from interacting with using a disabled state in code. Disabled tokens have low contrast and visual weight so that a user knows that it is not an active, interactable control.

#### Success

Success tokens style elements that confirm an action or objective were successfully completed.

#### Warning

Warning tokens style elements that show information that is not urgent but could require intervention. Warning tokens also style elements that are in-progress, incomplete, or pending.

#### Critical

Critical tokens style elements that require immediate attention or action and actions that are considered destructive within the experience. Critical tokens imply that an element or action is blocked or has an error that needs to be fixed.

#### Knockout

Knockout tokens, available for Border and Foreground categories, style elements that need a strong visual separation or contrast from other surrounding colors (typically darker values).

#### Overlay

Overlay tokens are transparent, background-only tokens that style the full page background that separates an overlay UI component, such as a modal, from the main UI elements underneath it by masking them.

## Learning Tokens

When patterns of color use emerge across components or categories of components, it is appropriate to consider creating a new domain of semantic tokens abstracted for the specific use cases the tokens serve in the system. Learning is a distinct domain of tokens specific to the context of Learning activities and environments. Learning tokens are not consumed outside of this context, Core tokens are intended to meet that need.

### Contexts

Learning token Layers share the following 6 contexts:

- Math
- Gems
- Streaks
- Due
- Mastery / Progress
- Role

#### Math

Math tokens style elements in Perseus Widgets that render [MathJax](https://www.mathjax.org/) content. These tokens follow MathJax’s specific formatting that do not have consistent alignment with our Primitives schema.

#### Gems

Gem tokens style elements that present Gem counts in the experience.

#### Streaks

Streak tokens style elements that present Streak metrics in the experience.

#### Due

Due tokens style elements that communicate the due date of an activity. Due tokens have two values: Due and Overdue. Overdue uses the Critical token schema from the Core tokens domain.

#### Mastery / Progress

Mastery / Progress tokens style elements that communicate a learner’s progress in completing a learning activity or mastering a subject. Mastery / Progress tokens use several token categories from the Core tokens domain.

#### Role

Role tokens style elements present in features directly tied to a user's account.

## Internal Tokens

The Internal domain differs in architecture from the Core and Learning domains. When patterns of color use emerge across components or categories of components, it is appropriate to consider creating a third tier of semantic tokens abstracted for the specific use cases the tokens serve in the system.

Internal tokens can reference states (Rest, Hover, Press, and Selected) for tokens such as the Action, Input, and Tile tokens, or Layers (Background, Border, Foreground) for Internal tokens that reference a context over a state, such as the Progress tokens.

We use Figma Variables to reduce the number of unique component instances we need to build, which is only possible by creating these component-specific tokens for Mode use in Figma.

**Internal tokens are consumed only by the Wonder Blocks system**. They are not to be used outside of official design system components in code, Core tokens should be used instead.

## Graphics Tokens

The Graphics domain styles custom graphics, illustrations, and icons in our system. These tokens cannot be used to style the interface, components, or Phosphor icons, only the custom graphic elements contained the interface or components.

### Contexts

- Palette
- Characters
- External Brands
- Gems
- Progress
- Role
- Streaks
- Neutral

#### Palette

Palette tokens style decorative graphic elements — elements without a specific, repeated purpose or context — throughout the Khan Academy platforms.

#### Characters

Character tokens style the visual appearance of Brand characters utilized across our experiences, including Khanmigo and Khanductor.

#### External Brands

External brand tokens style brand assets of third-party brands, such as the services allowed for third-party sign-in.

#### Gems

Gem tokens style the custom icons present with Gem counts in the experience.

#### Progress

Progress tokens style the custom icons present with elements that communicate a learner’s progress in completing a learning activity or mastering a subject.

#### Role

Role tokens style the custom icons present in features directly tied to a user's account.

#### Streaks

Streak tokens style the custom icons present with Streak metrics in the experience.

#### Neutral

Neutral tokens style the graphic backgrounds of the End of Task cards that display accessory unlocks.
