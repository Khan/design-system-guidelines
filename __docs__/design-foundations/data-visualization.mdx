# Data visualization

Data visualization turns learning data into decisions. Teachers and administrators use our charts to see who needs help, what's working, and what to do next. These foundations apply to every chart, wherever it appears. For how headings and controls are laid out on a page, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs">Data reports</a>. For the components built on these foundations, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#usage-and-purpose">Usage and purpose</a> in Data reports.

## Choosing a chart

Start from the question, then pick the simplest form that answers it. To choose a component, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#usage-and-purpose">Usage and purpose</a>. For when a number or a table works better than a chart, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#making-a-useful-chart">Making a useful chart</a>. Both are in Data reports.

### Forms to avoid

- Pie or donut charts with more than 3 slices. Use a bar chart.
- 3D charts. The depth distorts the values.
- Gauges or dials. Use a <a href="./?path=/docs/design-guidelines-components-data-visualization-progress-charts--docs">progress chart</a>.
- Area charts with overlapping series. Use a <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">trend chart</a> with lines.

## Anatomy

Use these names for chart parts across all data visualization guidance.

| Part | Purpose | Required |
| --- | --- | --- |
| Section heading (H2) | Names the topic above the chart container, e.g. "Mastery levels" | Yes, in large containers. See <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs#sizes">Sizes</a>. |
| Title (H3) | States the insight, directly above the chart | Yes, except in empty and error states |
| Description | Supporting context, time range, or filters applied | When it adds context |
| Axes and axis labels | Scale and units | Yes, unless values are labeled directly |
| Gridlines | Help estimate values | Optional; keep subtle |
| Data marks | Bars, lines, points, or segments that encode values | Yes |
| Data labels | Exact values on or next to marks | When exact values matter |
| Legend | Maps colors or patterns to series | Only when series can't be labeled directly |
| Tooltip | Details on hover or focus | Optional |
| Annotation | Calls out a notable point, goal, or threshold | Optional |
| Footer | When the data was last updated | Yes |

## Color

Chart colors come from the color palette and are chosen by **role**: what the color does in the chart. Color supports meaning but never carries it alone.

Primitives on this page are a visual reference for designers. Don't use them in code.

### Color roles

Choose the role by what the color shows, not where the data comes from. Assessment, Mastery, and Scores are for results, like levels and scores. How much or how far along, like how much of an assessment a class has finished, uses Progress and amounts. Motivation data always uses Motivation.

### Using color roles

<ul>
    <li><Do /> Give every filled mark a 1px outline in the role's outline color. Light fills don't reach 3:1 contrast on their own, so the outline carries it. Draw lines in the outline color at 2px.</li>
    <li><Do /> Keep a series' color the same across every chart in the view. Past four series, fold the rest into "Other" in Neutral gray, or use a table.</li>
    <li><Do /> To flag items that need action, highlight them with Emphasis and say what's wrong in the title or a label: "2 of 5 schools are behind schedule." Color points to the items, and the words say why.</li>
    <li><Do /> Use Progress and amounts for progress on anything, including assessments and mastery: "18 of 25 students finished the assessment."</li>
    <li><Dont /> Use Progress and amounts blue for results, like performance levels, mastery levels, or scores, or for motivation data. They have their own roles.</li>
    <li><Dont /> Use Magenta 30 as a fill outside motivation data.</li>
    <li><Dont /> Use Errors red for data, including low scores. Scores use lighter reds, so a low score doesn't read as a broken chart.</li>
</ul>

### Number formatting

| Rule | Example |
| --- | --- |
| Round to the precision that matters for the decision | 82%, not 82.37% |
| Use counts when the reader acts on individuals | "23 of 28 students completed it" |
| Use percentages to compare groups of different sizes | "82% of Period 1 vs. 64% of Period 3" |
| Pair them when comparing groups and the reader will follow up with individuals | "82% (23 of 28)" |
| Use thousands separators | 1,500, not 1500 |
| Write ordinals on the baseline, not as superscript | 8th, not 8ᵗʰ |
| Abbreviate large numbers | 1.2K, 3.4M |
| Always include units | 45 min, 12 skills |
| Use relative dates within 7 days | "2 days ago," "Due Friday" |
| Use full dates beyond 7 days | Oct 15, 2026 |

<ul>
    <li><Do /> Pair them when a teacher compares classes and will follow up with students: "Period 1: 82% (23 of 28)."</li>
    <li><Dont /> Pair them when the count is too large to act on: "82% (14,302 of 17,441)." Use the percentage alone.</li>
    <li><Dont /> Use counts alone to compare groups of different sizes: "23 of 28" vs. "12 of 14." Use percentages.</li>
</ul>

### Missing and zero values

Zero and missing are different and must look different.

- **Zero** is a real value. Show it as `0`.
- **Missing** means no data exists. Show it as `—` and explain why in a tooltip or footnote.

## Writing for data

- **Write chart titles as insights.** The title directly above a chart states the takeaway: "Students are moving up, but five have never left Beginning," not "Mastery levels." The section heading above the chart container names the topic, like "Mastery levels."
- **Leave the period off titles.** Titles are headings, so write them in sentence case with no ending punctuation, even when they're full sentences: "3 skills ahead of schedule."
- **Use plain language.** Avoid jargon like "cohort" or "variance" unless the audience expects it.
- **Name people consistently.** Use "students" for learners in a class context.
- **Label directly.** Put labels on the marks instead of relying on a legend.

## Accessibility

### Color must not be the only signal

Pair color with direct labels, patterns, shapes, or position. A chart must remain readable in grayscale.

A global display setting will add shapes, textures, and always-on values to charts for people who need them.

### Marks must meet contrast requirements

Data marks need 3:1 contrast against the background. Light fills meet this through their darker outline (see Fills and outlines). Text in charts follows standard text contrast (4.5:1).

### Provide a text alternative

Every chart needs a short summary of its key takeaway for screen readers. Charts with detailed data also need an accessible data table.

### Support keyboard access

Any information available on hover must also be available on keyboard focus.
